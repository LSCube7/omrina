# M2：本地识别、评分与复核

M2 以 M1 的单页 A4 模板和采集记录为输入。采集记录必须先提供完整的模板参数、schema 版本、`TemplateId` 和原图；应用重新生成模板并核对完整 ID 后才运行识别。纸上打印的短编号仅供人查看，不能代替模板身份校验。

## 数据流程

1. `CaptureStore` 保存扫描或导入的 PNG/JPEG 原图与关联 manifest，并可重新打开最近一条有效记录。
2. `Omrina.Platform` 用现有 SkiaSharp 解码图像、合成透明像素的白底灰度图，并限制输入文件和像素尺寸。
3. `Omrina.Core` 检测四角定位块和顶部方向标记，建立页面毫米坐标到图像像素坐标的变换，再测量每个选项的填涂情况。
4. 识别结果区分单选、空白、多选和不确定，附带定位、方向及填涂诊断。置信指标是启发式质量分数，不是正确率或概率。
5. 用户提供完整的标准答案后才能评分；填涂识别结果不会自动成为标准答案。人工修订以不可变快照和逐次审计记录保存。JSON/CSV 导出包含原识别、评分状态及可用的复核记录。

识别可以返回 `Accepted`、`ReviewRequired` 或 `Rejected`。拒绝的图像不产生可信分数；待复核结果在问题未解决前只能给出临时评分。未提供答案键时，只能导出识别与复核信息，不能显示数字分数。CSV 对逗号、换行和表格公式起始字符做转义。

## 桌面交互

采集页打开已保存的记录后，主窗口的 NavigationView 切换到“识别 / 复核”页。页面展示原图、模板关联、每题和每个选项的状态、诊断与质量指标；可取消识别、填写标准答案、记录人工修订及其原因，并通过系统文件保存对话框导出 JSON/CSV。识别和复核在本地执行，不经 M0 的只读健康接口或浏览器协议。

## 当前边界

- 识别算法针对本项目当前 schema 1 的 A4 模板；不自动识别其他版式或从纸面文字推断模板。
- 一张实物填涂扫描可用于本机验证，但单张样本不能证明普遍准确率。原图、采集 manifest 和个人结果保持本地，不放入仓库。
- 纸张实际尺寸与打印比例测量、不同扫描设备/分辨率的重复样本、macOS/Linux 实机和三平台 CI 仍按既定安排暂缓。
- 浏览器业务连接、任务和授权协议属于后续里程碑；M2 不把扫描设备接口开放给网页。

实际测试命令、通过项和未验证项见 [验证记录](../development/validation.md)。
