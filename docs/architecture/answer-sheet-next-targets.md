# OMRINA 学校答题纸下一阶段目标

更新日期：2026-10-03（学校版式首轮实现后的讨论修订）。

本文记录新增目标、尺寸更正及配套设计方案，供后续实现与验收使用。**尺寸规则与 0.1 mm 精度已完成初步接入；题组模型／编辑／排版和混排／分区已接入；整组裁切／批阅与 Data Matrix 尚未实现。** 已有能力和实际通过项见 [验证记录](../development/validation.md)，此前约定见 [UI/UX 与答题纸设计约定](ui-ux-and-answer-sheet.md)。

## 1. 本轮确认与优先级

| 项目 | 最新目标 | 当前代码差距 |
| --- | --- | --- |
| 填涂框尺寸 | 矩形高度为正值且 ≤2 mm，宽度不设统一数值上限；圆形框直径 ≤2 mm | 新建已修正，宽框按实际空间排版；旧开发版不保证兼容；实纸待验收 |
| 毫米步进 | 修复 0.1 mm 步进漂移，显示、保存、边界校验与打印尺寸一致 | 已按十分之一毫米网格校验并归一浮点漂移；手工非网格输入拒绝，UI 交互待验收 |
| 题组 | 显式定义题组，**按题组裁切**；评分仍精确到题目／小题 | 已提供题组模型、编辑和满栏几何；采集／批阅仍按单题区域，整组裁切待接入 |
| 排版 | 客观题与主观题支持混排，也支持分开排 | 已支持 Mixed／Separated 题组排序；首版每组限同题型，不支持跨栏／跨页组 |
| 页面机读码 | **Data Matrix 作为首选码制**，控制信息量与单格尺寸 | 当前使用包含完整页面元数据 JSON 的 QR Code |

这些目标不改变本地引擎、WinUI 3／Uno 桌面、本机服务及无 UI TypeScript SDK 的分工，不新增 Web UI，不授权新增依赖或下载。

## 2. 延续的版式要求

- 纸张仅为 A4 纵向或 A3 横向；用户选择，A3 支持两栏／三栏。
- 同时支持独立答题卡和包含题目正文的答题纸。
- A3 考生信息区始终位于首栏顶部；填涂示例与考试／页面机读码处于同一信息区。
- 考号仍支持条码或数字涂卡；数字与选择题字母共用框内／框外位置设置。
- 反面可不重复考生身份区，但必须保留考试／页面机读标识；不能仅凭考试码猜测考生归属。
- 答题区域在生成时定义，扫描与批阅复用不可覆盖的版式版本，不要求阅卷者重新画框。
- 标准答案和评分细则不输出到学生用纸。未确认身份、缺页或未完成批阅时，不生成学生最终整卷成绩。
- LOGO 继续预留；不提取、复制或提交用户的 `design.png`。

## 3. 尺寸与精度

### 3.1 填涂框规则

- 矩形：高度 `(0,2] mm`，宽度为有限正值，不再使用统一的 2 mm 宽度上限。
- 圆形：宽高相等，直径 `(0,2] mm`。
- 2 mm 合法，超过高度／直径上限不合法。主观题答题区和题组扫描框不受此 2 mm 限制。
- 宽度仍受实际栏宽与排版约束；无法容纳时明确提示，不能互相重叠、覆盖字母／数字或静默缩放。
- 选择题和考号涂卡的间距随实际框宽计算，不沿用只适合旧宽度的固定步距。
- 框内印字属于印刷基线，识别时不能将字母或数字笔画当作学生填涂。

### 3.2 精度方案

已确认要解决的是：**0.1 mm 步进必须准确，不能仅把浮点结果格式化显示为一位小数。**

初步实现沿用现有毫米数值字段，不新增序列化字段：用 `round(mm × 10)` 得到十分之一毫米单位，检查其为安全整数且与输入相差不超过 `1e-9`，再除以 10 规范化。这样消除 0.1 mm 步进的双精度漂移，而不是仅修改显示格式。Core 与 SDK 新建校验使用同一网格；版式预览与打印复用规范化后的尺寸。

手工输入如 `1.85 mm` 不静默舍入，生成时提示调整。按项目 [AGENTS.md](../../AGENTS.md)，开发版本不保留旧尺寸／旧精度兼容路径。主观题高度的步进和范围独立定义，本轮未统一量化。桌面连续加减与重开后的显示仍待人工验收。

## 4. 题组结构与编辑

建议关系：

```text
考试 → 答题纸版本 → 页面 → 题组 → 题目／小题
```

- 题组是排版与裁切单位，题目／小题是标准答案、评分与状态记录单位。
- 题组包含稳定标识、标题、顺序、成员题目及版式属性；保留原试卷题号，不因重新分组或排版重新编号。
- 支持创建、命名、排序题组，并调整题目所属题组及组内顺序。
- 默认可按题型建组；首版每组只含一种题型；同组混合不同题型的小题仍待确定。
- 同一题组可以使用一个大外框，并在内部生成横线、分隔线、题号和分值。
- 每道题的作答空间仍可独立调整。题组高度由内部排版、标题、间距及成员作答空间计算；调整一题不覆写其他题的高度。

用户提供的参考图用于借鉴横向分栏、紧凑客观题块、题组外框、内部横线及信息区组织；不复制图片中的个人信息、实际答卷或二维码。边缘和底部标记的编码用途不能仅凭外观确定，不直接照搬。

多选题、填空题、多小题综合题的识别和评分规则需要分别定义；看到参考图中的题型不等于这些规则已实现或已全部定稿。

## 5. 混排与分区排版

| 模式 | 目标行为 |
| --- | --- |
| 按题组顺序混排 | 客观题组和主观题组按用户指定的题组顺序出现 |
| 客观题／主观题分区 | 客观题组集中排列，主观题组另一区域排列；各区内部保留指定顺序 |

- 独立答题卡中的客观题采用紧凑题组，可在题组内部安排多个题号块，避免每题都占用较大的独立纵向空间。
- 主观题按题组外框及内部结构排版。包含正文模式根据正文与作答空间重新排版，不整体缩放填涂框。
- 混排和分区不改变原题号、标准答案、分值或身份关联。
- 分区与分页策略分开：分区不默认强制另起一页；是否提供“分区另起栏／页”选项待定。
- 综合题组的分区归类方式需在支持该能力前明确，不能静默拆开一个题组。

## 6. 按题组裁切与批阅

- **题组扫描框宽度固定为所在栏可用宽度的 100%。** 客观题组内部的题号块或主观题组内的小题可以分列，但不改变整组扫描框宽度。
- 生成时记录题组所在页、外部裁切几何，以及内部题目／选项的相对位置；预览、打印、识别和裁切共用这一版式。
- 扫描先验证页面身份并完成定位校正，再按题组区域提取图像。保留原图、页面版本和题组标识。
- 人工批阅展示整张题组图，并提供组内题目／小题的分数、评语与状态；逐题评分后形成题组小计。
- 客观题识别仍按组内题目／选项几何读取，不能因整组裁图丢失题号、选项或印刷基线。
- 题组图与题目评分记录分开关联，不强制“一题一张图”；题组图不能被误认成某道题的独立答案。
- OCR／AI 后续可接收整组图，返回与题目标识对应的识别或评分建议；人工确认仍是独立步骤，本轮不接入模型。
- 无匹配版式、区域缺失、页面错配、定位失败或题组越界时明确拒绝裁切，不输出看似正常的错误题图。

首版已按一个题组在同一页同一栏内完整放置实现，空间不足时整组换栏／换页；超过一栏容量时提示调整。跨栏／跨页题组需要片段标识、拼图与完整性规则，暂作为待定范围。

## 7. Data Matrix 页面标识

### 7.1 目标与建议协议

- 页面机读码首选 Data Matrix；考号条码／涂卡继续独立配置，不自动换成 Data Matrix。
- 不继续把完整 JSON、长 ID、字段名和完整模板哈希全部写进纸上码。
- 建议使用普通 Data Matrix ECC 200；具体编码选项和库适配需检查现有依赖，若需新依赖另行申请。
- 建议载荷为“编码格式版本 + 不可变页面短标识”。完整考试 ID、答题纸版本、页码、正反面、模板哈希和几何由本地对应表读取。
- 短标识须具备足够的唯一性并在注册时检查冲突，不使用可被重复覆盖的页面序号代替唯一标识。
- 页面码识别与查询不要求联网；未知短标识、对应资料未导入或版式不匹配时进入明确的待处理状态，不猜测布局。

短标识方案需要配套考试／模板资料导出与导入，支持另一台电脑离线查找相同版式；导入时校验身份冲突和完整性。具体载荷长度、字符集、校验与导出格式尚未锁定。

### 7.2 印刷与扫描

- 改码制不能代替控制信息量、单格尺寸、留白、黑白对比和真实打印质量。
- 初始可将每格 0.5–0.7 mm 作为试验参数；不将其当成已验收的最终规格或准确率保证。
- 不用固定外框强行容纳任意数据密度，不压缩留白，不把边框、文字或学生作答放入机读码留白区。
- 每页包括无考生身份区的反面，都保留独立可读的页面码。
- 资料依据：[GS1 Data Matrix 指南](https://ref.gs1.org/guidelines/datamatrix/)。本项目不据此自动采用 GS1 商品标识业务规则。

## 8. 模块影响与实施顺序建议

| 模块 | 目标变化 |
| --- | --- |
| Core | 题组／题目关系、两种排序模式、满栏组几何、尺寸精度、Data Matrix 页面标识与识别 |
| 模板编辑／打印 | 题组编辑、紧凑客观题块、组内作答空间、按组分页与同版式预览打印 |
| 采集／持久化 | 保存原页面身份及题组几何，短标识对应资料，受验证的资料导入／导出 |
| 人工批阅 | 组图查看、组内逐题评分与状态、小计和完整性提示 |
| Protocol／SDK | 准确的题组类型、组图资源和评分对应关系，继续使用授权资源 ID，不开放任意本地路径 |

建议按以下顺序小步实现：

1. 修正填涂框尺寸规则和 0.1 mm 精度，补齐边界回归。
2. 确定题组数据和版本规则，接入两种排序与题组几何。
3. 接入题组编辑、同版式打印、整组裁切与组内逐题批阅。
4. 接入 Data Matrix 短标识与资料导入／导出，完成离线页面查找链路。
5. 同步本机服务与 SDK，补充业务回归，再做实纸与界面验收。

按项目 [AGENTS.md](../../AGENTS.md)，当前为开发版本，模板与接口可直接按当前目标调整，不要求旧版模板、扫描或批阅记录继续可用，不保留兼容层或迁移逻辑。此约定不授权删除、覆盖或清理用户资料。

## 9. 验收目标

- 矩形高度 2 mm、圆形直径 2 mm 可用，超过上限被拒绝；矩形宽度大于 2 mm 在栏内可正常排版、识别，超栏或重叠被拒绝。
- 多次 0.1 mm 加减、输入与重开后尺寸一致，不产生显示正常但校验失败的浮点漂移。
- 题组创建、排序、成员调整、混排／分区切换后，题号、分值与成员关系保持正确。
- 逐题空间改变时，整组外框、实际纸面和裁切几何同步；A3 两栏／三栏及 A4 均为整组满栏宽度。
- 扫描整组图与原图区域相符；同组多题可分别评分，重开、修订和导出不混淆组分数与题分数。
- Data Matrix 在真实打印、扫描与拍照样本中验证；覆盖方向、缩放、低分辨率、模糊、污染及裁边，不用合成测试代替实纸准确率验收。
- 已导入模板资料可在另一台电脑离线识别；缺少资料、未知标识、冲突、错考试／错版式／错页均明确处理。
- 当前题组与批阅继续遵守授权隔离；未知学生身份不能变成最终成绩。旧开发版读取不作为验收条件。

本轮不运行 computer-use、不操作真实扫描仪或打印机，不启动程序。UI、高 DPI、Data Matrix 实纸规格、跨页关联、整卷综合成绩、图片正文及 OCR／AI 的未验收状态保持明确。

## 11. 题组模型与排版交付（2026-10-03）

- Core 新增 `SchoolQuestionGroupDefinition`、`SchoolLayoutOrder` 与页面 `SchoolGroups`；显式组成员完整且唯一覆盖题目，每组同题型，保留原题号与分值。
- 桌面可新建／命名题组、删除空组、调整组顺序、题目所属组与组内顺序，选择混排或客观／主观分区；生成时保存归一化组定义。
- 整组在同栏／同页放置，空间不足整组换栏／换页，超出完整栏容量明确拒绝。组框占满栏宽；主观题高度仍逐题设置，独立答题卡客观题组内为约 6 mm 的紧凑纵向行。本批未实现组内多题号块分列。
- SDK 与本机服务接收严格组定义，学校模板摘要返回组几何和成员；没有新增整组图资源或批阅接口。
- 按开发期规则删除旧尺寸回放分支和对应旧格式 fixture；不删除任何用户文件或数据。存储字段仍为 schema3，但当前快照必须含 `groups/layoutOrder`，旧开发版不要求可读。
- 验证记录见 [validation](../development/validation.md)。下一批优先整组裁切、组内逐题批阅及相应 SDK 资源，再推进 Data Matrix。
