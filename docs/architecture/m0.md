# OMRINA M0 验证边界

## 目标

确认 Windows 桌面 UI 与扫描库可以协作，并为后续第三方应用授权连接本机建立边界。OMRINA 是计划中的本地 Integration Agent，当前 SDK 只有健康检查客户端，服务端也只有只读健康接口，不意味着完整业务、设备权限或生产连接协议已经实现。桌面项目已引入 Uno.Sdk 6.7.30，提供 Windows 与 `net10.0-desktop` 双 target；Windows 导航壳使用 WinUI 3 / Windows App SDK，桌面 target 使用 Uno Skia。

## 产品边界

- Windows 本地应用当前可以操作模板和图像采集；任务、复核和结果流程尚未实现。macOS / Linux 属于桌面目标，尚待对应实现和验收。
- TypeScript SDK 当前只提供回环 `/health` 健康检查，不包含 Web UI 或设备、任务业务调用。
- `Omrina.Core`、`Omrina.Protocol`、`Omrina.Scanning` 和 `Omrina.Server` 保持平台无关；其中 Core、Protocol、Scanning 和 Server 目前只实现各自的 M0/M1 最小契约。`Omrina.Platform` 与桌面入口已引入平台边界接口，`Omrina.Desktop` 当前承载 Windows/Skia 双 target 的单窗口导航壳。
- 当前窗口提供状态、模板、采集、设置和关于页面，并使用自定义 TitleBar；模板页与采集页在主窗口内缓存。旧版 MainWindow“扫描测试纸”入口已退役，图像导入与扫描统一由采集页交给 `CaptureStore`。这些描述是迁移中的代码事实，不是 UI 验收结论。
- Uno UI 已通过 Uno.Sdk 6.7.30 引入；Windows target 使用 Windows App SDK / WinUI 3，`net10.0-desktop` 使用 Uno Skia，其他 target 不能假定 WinRT API 可用。平台能力以最终代码和测试结果为准。
- Windows `Omrina.Desktop` 通过 NAPS2 接入 TWAIN/WIA；扫描辅助进程负责位数兼容。macOS/Linux 系统打印尚未适配，macOS/Linux 实机与设备后端尚未测试。
- 任务管理、持久化以及网页断开后的硬件任务行为属于后续服务设计；当前服务只有健康检查接口。

三平台 CI 当前暂缓。恢复 CI 后再补充 Windows、Ubuntu 和 macOS 的 restore、build、unit tests、publish 与基础 smoke tests；CI 结果也不能替代 macOS / Linux 的真实设备、权限和打包验收。

## M0 测试层次

1. SDK 单元测试：模拟服务响应，验证超时、取消、协议与错误。
2. 桌面构建：项目已纳入 Windows 与 Uno Skia Desktop 双 target；构建、Core/Capture/SDK 测试和 UI 验收按当前验证记录维护。macOS/Linux 实机验证与三平台 CI 暂缓。
3. 桌面运行：检查窗口启动、设备枚举、线程与退出。
4. 真实扫描：使用已准备且授权读取的测试纸；连接成功不能替代扫描成功。
5. 浏览器联调：从 HTTPS 页面访问回环服务，分别验证 HTTP 与 WebSocket；测试允许、拒绝和撤销权限。

只有实际执行的层次才记录为通过。原型和模拟接口不计为真实设备或浏览器验证。

## 后续连接安全要求

服务仅监听回环地址。配对窗口显示精确网站来源。设备操作和图像访问必须同时检查来源与有效凭据；CORS 不是身份认证。WebSocket 校验与 HTTP 一致。任务数据不能对所有配对网站默认共享。禁止任意文件路径读取与命令执行。

任务请求需要幂等标识，复核修改需要版本检查，事件需要序号与状态恢复接口。取消扫描后保存已完成页面，不能自动重发开始扫描。
