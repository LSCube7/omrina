# M1：模板、打印与采集

M1 在本地引擎中实现模板几何，再由 WinUI 提供参数输入、预览、打印和采集操作。TypeScript SDK 的业务接入留在 M3；本阶段不把设备接口开放给网页。当前代码已经覆盖 M1 的主要本地流程，但实物打印、填涂、再扫描闭环尚未完成，因此不能声称 M1 全部验收。

## 实施顺序

1. 单页 A4 模板核心：以毫米记录定位标记、题号和选项坐标；验证题数、选项数和页面容量；生成可打印的 SVG。
2. WinUI 模板操作：参数输入、预览、保存；预览使用同一份几何数据，屏幕 DPI 不改变纸张尺寸。
3. 打印：通过系统打印流程输出，提供 100% 实际尺寸说明和校准方法，验证纸上标记的实际距离。
4. 图像采集：导入图像、选择扫描来源和分辨率、保存页面与模板关联；保留原图和来源记录，为后续方向处理保留输入，支持取消及错误重试。

第一步只建立模板核心，不代表完整 M1 验收。扫描普通测试纸不能证明模板识别准确率；只有使用生成并打印的模板完成填涂、扫描和后续识别验证，才能形成 M1 的实物闭环证据。

## 当前代码实现

### Core 模板与身份

`AnswerSheet.Core` 已实现单页 A4（210mm × 297mm）、1–44 题、每题 2–6 个选项、最多 24 个 Unicode 字符的单行标题。毫米坐标模型包含四个定位标记、题号、选项列标和填涂圆圈；SVG 使用物理纸张尺寸，独立于屏幕 DPI。

模板 schema 版本为 1。标题先使用 NFC 规范化，再由规范化标题、题数、选项数和 schema 版本生成完整小写 SHA-256 `TemplateId`。页面顶部有独立的 `orientation-top` 方向标记，并打印短编号，格式为 `AS1-{题数两位}x{选项数}-{TemplateId 前 8 位大写}`。SVG metadata 同时记录 schema、`TemplateId`、短编号、题数和选项数。

布局创建时会检查页面边界、填涂圆圈间距以及方向标记与其他元素的间隔；相同参数产生相同布局和 SVG。Core 回归程序目前包含 9 项检查，覆盖容量、边界、非法输入、XML 转义、确定性和模板身份。此前执行 `dotnet run --project tests/core/AnswerSheet.Core.Tests.csproj --no-restore -- --write-example` 已通过 9 项检查并生成 `artifacts/templates/m1-example-a4.svg`。这项结果只证明代码级几何和 SVG 行为，不代表打印实物比例正确。

### WinUI 模板操作

`MainWindow` 提供“新建答题纸模板”入口；`TemplateWindow` 使用 Core 的同一份毫米几何生成预览，并通过 `FileSavePicker` 和 `FileIO.WriteTextAsync` 保存 SVG。修改标题、题数或选项数会使当前预览失效，必须重新生成后才能保存、打印或导入图像。

2026-09-18 的真实 WinUI 软件级验证使用默认 20 题、每题 4 个选项的模板：预览显示短编号 `AS1-20x4-B7A4AFC5` 和顶部方向标记；取消保存时显示“已取消保存 SVG”，保存按钮恢复可用。实际保存的 `artifacts/templates/m1-ui-save-20260917.svg` 为 28,762 字节，XML 检查确认 A4 `210mm × 297mm`、`viewBox="0 0 210 297"`、80 个填涂圆圈、1 个方向标记，以及完整 `TemplateId` `b7a4afc51ac55b215158c8b31e1f49dc993786cafaad67e88fa66ce7d0394cf9`。

### 系统打印

`TemplatePrintController` 已接入 Windows 系统打印流程。打印页面按 A4 纵向的实际尺寸创建，并在分页阶段检查系统报告的纸张尺寸和 `ImageableRect` 可打印区域。纸张不是 A4 纵向，或打印机边距会裁切模板内容时，流程会报告错误并停止，不自动把模板缩放到其他纸张。系统任务的提交、取消和失败状态会回传到模板窗口。

软件级验证实际选定 Microsoft Print to PDF，预览为 1 页，状态显示“系统已接收打印任务。打印是否完成请以系统状态为准。”，打印后生成并保存 `artifacts/templates/m1-print-20260918.pdf`（170,787 字节）。`pdfinfo` 确认 Producer 为 Microsoft Print To PDF、1 页、595.276 × 841.89 pt（A4）、rotation 0、未加密；渲染页面已目视确认定位块、方向标记、编号、标题、列标和气泡清晰，无裁切、空白或重叠。该验证覆盖软件输出，不替代实体打印比例测量。

### 图像导入与扫描采集

`CaptureWindow` 支持用户明确选择 PNG/JPEG 图像，`CaptureStore` 会校验扩展名、实际编码、尺寸和文件大小，并把图像与模板引用关联。每条记录保留原始图像，并生成 `manifest.json`，记录来源（导入或扫描）、模板 schema、`TemplateId`、规范化标题、题数、选项数、像素尺寸和文件大小。

保存采用暂存目录：原图和 manifest 均写入本次生成的暂存目录，manifest 写完后再将整个目录移动到最终采集目录。取消、校验失败或写入失败会清理该暂存目录，已存在的采集记录不会被覆盖。

扫描入口支持 WIA 和 TWAIN 设备，固定使用平板、A4、非原生驱动界面，并提供 150、300、600 DPI。当前流程只取得首张图像，先写入应用拥有的临时 PNG，再交给同一份 `CaptureStore` 保存和关联模板；取消或失败不会自动重发扫描。

软件级验证从已有授权测试纸导入 PNG，界面显示 2481 × 3506，并成功关联模板 ID `b7a4afc51ac55b215158c8b31e1f49dc993786cafaad67e88fa66ce7d0394cf9`。本次未执行物理扫描；WIA/TWAIN 设备采集仍需在实体打印、填涂后再扫描闭环中验证。

## 验证状态

下面把“代码已实现”和“已通过运行验证”分开记录：

- Core schema 1、`TemplateId`、NFC 标题、短编号、顶部方向标记以及几何检查已实现；Core 9 项回归测试此前已通过。
- 打印控制器、PNG/JPEG 导入、CaptureStore 原图与 manifest 保存、WIA/TWAIN 平板扫描和 150/300/600 DPI 选择已实现于代码；CaptureStore 的 5 项回归检查已通过。模板 UI、SVG 文件、PNG 导入关联和 Print to PDF 软件路径已完成验证；实际 WIA/TWAIN 设备采集和实体闭环仍待确认。
- M1 的实体打印比例测量、填涂后再扫描闭环尚未完成。现有普通测试纸扫描只能证明设备路径的基础能力，不能证明模板识别或评分准确率。
- M0 的 HTTPS 浏览器访问、WebSocket、配对授权和授权撤销仍待后续验证。当前本地健康接口不能替代生产连接协议。

## 验收标准

- 合法模板的标记和填涂区域均在 A4 页面内，选项之间不重叠；非法输入和超容量请求明确失败。
- 相同参数产生相同几何与 SVG；标题不能注入 SVG 元素或外部资源；模板身份在等价 NFC 标题下保持一致。
- UI 高缩放与窄窗口下仍可输入参数和执行操作；预览缩放不改变毫米坐标。
- 打印输出经实物测量确认比例，至少完成一张生成模板的打印、填涂、扫描闭环。
- PNG/JPEG 导入和 WIA/TWAIN 扫描都保留原图并写入正确模板 manifest；采集失败、用户取消与成功保存均有明确结果；不自动重发扫描。

## 尚待验证的 M0 条件

HTTPS 浏览器访问回环服务的权限流程、WebSocket 连接以及授权撤销仍待验证。当前只有只读健康接口，不能声称生产连接协议已完成。M1 纯本地模板、打印和采集代码可独立推进，但仍需完成本节所列的实物和运行验证。
