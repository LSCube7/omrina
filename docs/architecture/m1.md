# M1：模板、打印与采集

M1 在本地引擎中实现模板几何，再由 WinUI 提供参数输入、预览、打印和采集操作。TypeScript SDK 的业务接入留在 M3；本阶段不把设备接口开放给网页。

## 实施顺序

1. 单页 A4 模板核心：以毫米记录定位标记、题号和选项坐标；验证题数、选项数和页面容量；生成可打印的 SVG。
2. WinUI 模板操作：参数输入、预览、保存；预览使用同一份几何数据，屏幕 DPI 不改变纸张尺寸。
3. 打印：通过系统打印流程输出，提供 100% 实际尺寸说明和校准方法，验证纸上标记的实际距离。
4. 图像采集：导入图像、选择扫描来源和分辨率、保存页面与模板关联；保留原图，记录方向差异，支持取消及错误重试。

第一步只建立模板核心，不代表完整 M1 验收。扫描已有普通测试纸不能证明模板识别准确率。

## 当前实现与验证

2026-09-16：`AnswerSheet.Core` 已实现单页 A4、1–44 题、每题 2–6 个选项、最多 24 个 Unicode 字符的单行标题。毫米坐标模型包含定位标记、题号、选项列标与填涂圆圈；SVG 使用物理纸张尺寸，独立于屏幕 DPI。

执行 `dotnet run --project tests/core/AnswerSheet.Core.Tests.csproj --no-restore -- --write-example`，7 项回归测试通过，覆盖容量、溢出、圆圈间距、页面边界、非法参数、XML 转义与确定性。首次运行前需恢复本地项目；核心与测试项目均无外部包依赖。

示例位于忽略提交的 `artifacts/templates/m1-example-a4.svg`。30 题、4 选项的示例已经真实浏览器渲染检查，中文标题、四角标记、选项列标与题号可见。此检查不代表打印实物比例验证。

四个定位标记当前形状相同，尚不能独立判定页面的 180° 方向，也未编码模板身份；进入 M2 识别前需补足方向和模板匹配设计。

### WinUI 模板操作状态（2026-09-17）

桌面项目已引用 `AnswerSheet.Core`，`MainWindow` 提供“新建答题纸模板”入口，`TemplateWindow` 使用同一份毫米几何生成屏幕预览，并通过 `FileSavePicker` 保存 SVG。参数变化会使当前预览失效，必须重新生成后才能保存；保存实现使用 `FileIO.WriteTextAsync`。

主代理前一轮已在实际 WinUI 窗口确认默认 20 题、每题 4 个选项的预览，标题变化后的保存状态，以及重新生成后的标题和保存状态；`FileSavePicker` 也已实际打开。最新 x64 `--no-restore` 构建 Core 与 Desktop 均为 0 警告、0 错误。真实保存和取消保存尚未验收：本轮 Computer Use 点击模板入口时遇到 `coordinate input geometry is unavailable`，之后又检测到用户输入，未继续执行输入操作。

这一步只完成模板操作原型，不能替代打印实物比例验证、图像导入或扫描闭环；M0 HTTPS / WebSocket 连接也仍待验证。

## 验收标准

- 合法模板的标记和填涂区域均在 A4 页面内，选项之间不重叠；非法输入和超容量请求明确失败。
- 相同参数产生相同几何与 SVG；标题不能注入 SVG 元素或外部资源。
- UI 高缩放与窄窗口下仍可输入参数和执行操作；预览缩放不改变毫米坐标。
- 打印输出经实物测量确认比例，至少完成一张模板的打印、填涂、扫描闭环。
- 采集失败、用户取消与成功保存均有明确结果；不自动重发扫描。

## 尚待验证的 M0 条件

HTTPS 浏览器访问回环服务的权限流程、WebSocket 连接以及授权撤销仍待验证。当前只有只读健康接口，不能声称生产连接协议已完成。M1 纯本地模板工作可独立推进。
