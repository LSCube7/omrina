# M1：模板、打印与采集

M1 在本地引擎中实现模板几何，再由桌面 UI 提供参数输入、预览、打印和采集操作。桌面项目已引入 Uno.Sdk 6.7.30，提供 Windows 与 `net10.0-desktop` 双 target；Windows 导航壳使用 WinUI 3 / Windows App SDK，桌面 target 使用 Uno Skia。单窗口使用 NavigationView、TitleBar，以及状态、模板、采集、设置、关于页面；模板页与采集页缓存于主窗口。TypeScript SDK 的业务接入留在 M3；本阶段不把设备接口开放给网页。2026-09-18 已完成一张生成模板的打印、填涂和本地应用扫描，目视确认四角定位与方向标记完整；纸面尺寸测量和 M2 自动识别仍未完成。macOS/Linux 系统打印尚未适配，macOS/Linux 实机尚未测试，三平台测试暂缓，因此不能声称 M1 全部验收。

## 实施顺序

1. 单页 A4 模板核心：以毫米记录定位标记、题号和选项坐标；验证题数、选项数和页面容量；生成可打印的 SVG。
2. 桌面 UI 模板操作：通过单窗口导航的模板页完成参数输入、预览和保存；预览使用同一份几何数据，屏幕 DPI 不改变纸张尺寸。模板页在主窗口内缓存。
3. 打印：通过系统打印流程输出，提供 100% 实际尺寸说明和校准方法；软件输出已验证，纸面标记的实际距离仍待测量。
4. 图像采集：通过采集页导入图像、选择扫描来源和分辨率、保存页面与模板关联；保留原图和来源记录，为后续方向处理保留输入，支持取消及错误重试。旧版 MainWindow“扫描测试纸”入口已退役，导入和扫描统一交给 `CaptureStore`。生成模板的打印、填涂和本地应用扫描已完成一轮实物验证。

第一步只建立模板核心，不代表完整 M1 验收。当前实物验证确认了生成模板可以打印、填涂并由本地应用采集，且四角定位与方向标记完整；它不包含纸面尺寸测量，也不证明模板识别准确率。M2 的识别、评分和人工复核尚未实现。

## 当前代码实现

### Core 模板与身份

`Omrina.Core` 已实现单页 A4（210mm × 297mm）、1–44 题、每题 2–6 个选项、最多 24 个 Unicode 字符的单行标题。毫米坐标模型包含四个定位标记、题号、选项列标和填涂圆圈；SVG 使用物理纸张尺寸，独立于屏幕 DPI。

模板 schema 版本为 1。标题先使用 NFC 规范化，再由规范化标题、题数、选项数和 schema 版本生成完整小写 SHA-256 `TemplateId`。页面顶部有独立的 `orientation-top` 方向标记，并打印短编号，格式为 `AS1-{题数两位}x{选项数}-{TemplateId 前 8 位大写}`。SVG metadata 同时记录 schema、`TemplateId`、短编号、题数和选项数。

布局创建时会检查页面边界、填涂圆圈间距以及方向标记与其他元素的间隔；相同参数产生相同布局和 SVG。Core 回归程序目前包含 9 项检查，覆盖容量、边界、非法输入、XML 转义、确定性和模板身份。这项结果只证明代码级几何和 SVG 行为，不代表打印实物比例正确。

### 桌面导航与模板操作

主窗口通过 NavigationView 提供“状态”“模板”“采集”“设置”“关于”页面，并使用自定义 TitleBar 显示当前页面。模板页使用 `Omrina.Core` 的同一份毫米几何生成预览，并通过系统文件选择器保存 SVG；采集页负责 PNG/JPEG 导入和扫描保存。模板页与采集页实例在主窗口内缓存，模板页发起采集时复用同一个采集页。修改标题、题数或选项数会使当前预览失效，必须重新生成后才能保存、打印或导入图像。

2026-09-18 的桌面软件级验证使用默认 20 题、每题 4 个选项的模板：预览显示短编号 `AS1-20x4-B7A4AFC5` 和顶部方向标记；取消保存时显示“已取消保存 SVG”，保存按钮恢复可用；XML 检查确认 A4 `210mm × 297mm`、80 个填涂圆圈和 1 个方向标记。

### 系统打印

`TemplatePrintController` 已接入 Windows 系统打印流程。打印页面按 A4 纵向的实际尺寸创建，并在分页阶段检查系统报告的纸张尺寸和 `ImageableRect` 可打印区域。纸张不是 A4 纵向，或打印机边距会裁切模板内容时，流程会报告错误并停止，不自动把模板缩放到其他纸张。系统任务的提交、取消和失败状态会回传到模板页。

软件级验证实际选定 Microsoft Print to PDF，预览为 1 页，状态显示“系统已接收打印任务。打印是否完成请以系统状态为准。”；PDF 元数据确认 1 页 A4、未加密，渲染页面已目视确认定位块、方向标记、编号、标题、列标和气泡清晰，无裁切、空白或重叠。该验证覆盖软件输出，不替代实体打印比例测量。

### 图像导入与扫描采集

采集页支持用户明确选择 PNG/JPEG 图像，`CaptureStore` 会校验扩展名、实际编码、尺寸和文件大小，并把图像与模板引用关联。每条记录保留原始图像，并生成 `manifest.json`，记录来源（导入或扫描）、模板 schema、`TemplateId`、规范化标题、题数、选项数、像素尺寸和文件大小。

保存采用暂存目录：原图和 manifest 均写入本次生成的暂存目录，manifest 写完后再将整个目录移动到最终采集目录。取消、校验失败或写入失败会清理该暂存目录，已存在的采集记录不会被覆盖。

扫描入口支持 WIA 和 TWAIN 设备，固定使用平板、A4、非原生驱动界面，并提供 150、300、600 DPI。当前流程只取得首张图像，先写入应用拥有的临时 PNG，再交给同一份 `CaptureStore` 保存和关联模板；取消或失败不会自动重发扫描。

软件级验证确认 PNG 导入界面可以显示 2481 × 3506 的采集图，并关联模板身份。随后使用生成模板完成打印、填涂并通过本地应用扫描，目视确认页面四角定位与方向标记完整。纸面实际尺寸尚未测量，M2 识别尚未实现。

## 验证状态

下面把“代码已实现”和“已通过运行验证”分开记录：

- Core schema 1、`TemplateId`、NFC 标题、短编号、顶部方向标记以及几何检查已实现；Core 回归结果以当前迁移后的最终构建为准。
- 打印控制器、PNG/JPEG 导入、CaptureStore 原图与 manifest 保存、WIA/TWAIN 平板扫描和 150/300/600 DPI 选择已实现于代码；Windows 单窗口导航 UI、Capture 回归和 SDK 测试按当前验证记录维护。macOS/Linux 系统打印与实机设备验收仍待补充。
- M1 的纸面打印比例测量尚未完成；实物扫描的目视检查不等同于模板识别或评分准确率。M2 的识别、评分和人工复核尚未实现。
- M0 的 HTTPS 浏览器访问、WebSocket、配对授权和授权撤销仍待后续验证。当前本地健康接口不能替代生产连接协议。

## 验收标准

以下是完整 M1 验收标准；括号内标出当前验证状态。

- 合法模板的标记和填涂区域均在 A4 页面内，选项之间不重叠；非法输入和超容量请求明确失败。
- 相同参数产生相同几何与 SVG；标题不能注入 SVG 元素或外部资源；模板身份在等价 NFC 标题下保持一致。
- UI 高缩放与窄窗口下仍可输入参数和执行操作；预览缩放不改变毫米坐标。
- 打印输出经实物测量确认比例（当前未完成）。
- 至少完成一张生成模板的打印、填涂、扫描闭环（Windows 既有流程已完成一轮，目视确认四角定位与方向标记完整；本轮 UI 验收未执行实体扫描或打印）。
- PNG/JPEG 导入和 WIA/TWAIN 扫描都保留原图并写入正确模板 manifest；采集失败、用户取消与成功保存均有明确结果；不自动重发扫描（Windows Capture 回归已覆盖导入、取消和失败清理；设备实机仍待补）。
