# M3：本地业务服务与 TypeScript SDK

M3 把已有的模板、采集、识别、评分、复核和导出能力接入本机服务，由无 UI 的 TypeScript SDK 调用。桌面仍负责设备适配与网站授权确认，Core 保持平台无关。服务端不依赖桌面 UI 类型。

## 实施顺序

1. 固定版本化 HTTP/JSON 契约和错误码，建立网站来源、配对码、凭据、过期与撤销规则。
2. 在桌面设置页接入待配对申请和已授权网站；将已有本地业务注入服务端。
3. 接入异步任务、创建幂等键、独立取消、结果版本检查，以及 WebSocket 状态事件。
4. 实现无运行时依赖的 SDK，生成 JavaScript 与 TypeScript 声明文件，并验证真实 HTTP/WebSocket 与浏览器跨来源调用。

详细路由、参数、大小上限与状态见 [M3 服务契约](m3-contract.md)。

## 授权与资源边界

网站先申请配对，本地设置页显示完整来源及所申请的能力。只有用户在本地允许后才显示一次性配对码；SDK 交换凭据时必须保持相同来源。业务请求同时验证来源与凭据，CORS 响应本身不授予业务权限。WebSocket 首条消息认证成功后才发送任务事件，撤销会终止该授权的访问和连接。

任务、采集记录与识别结果按授权归属隔离。网页通过受控 ID 引用结果，接口不接收任意本地路径。创建任务需要幂等键；超时和网页断线只代表客户端停止等待，不会自动重复扫描。取消通过独立接口明确提出，复核修改通过预期版本避免覆盖其他修改。

当前开发版本的授权与业务索引保存在进程内存，应用重启后需重新配对；已保存的原图和 manifest 继续保留在本地。SDK 的凭据只保存在客户端实例内存，宿主应用负责它自身的会话生命周期。

## 验收要求

- 无来源、来源与凭据错配、过期、拒绝和撤销路径明确失败；不同授权不能读取或修改彼此资源。
- 模板生成、合成图上传、识别、评分、连续复核、导出能通过 SDK 完整调用；设备与扫描使用模拟实现验证，实物扫描单独授权与验收。
- 幂等重复请求不创建重复任务，不同内容重用幂等键报冲突；取消、超限、低质量识别及复核版本冲突有明确状态。
- WebSocket 事件序号单调，断线可通过任务列表恢复状态，撤销后停止接收事件。
- SDK 单元测试、正式类型检查和构建通过；浏览器真实跨来源检查与 HTTP/WebSocket 代码级测试分开记录。

macOS/Linux 实机、三平台 CI、公网 HTTPS 网站到本机的浏览器权限及设备兼容性按现有待验收范围记录。实际通过项见 [验证记录](../development/validation.md)。
