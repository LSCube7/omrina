# M4：分发准备与兼容性验收

M4 将 M3 的本机服务与无 UI SDK 整理成可重复构建、可检查的交付物。当前先完成离线开发验证包与 SDK 消费者检查，再安排安装器、签名、真实网站和设备兼容性验收。

## 本轮范围

1. Windows x64 开发验证包：复用现有项目和已缓存依赖，在独立目录进行匹配 Release 配置的本地恢复，再发布和检查；不联网或下载。输出独立目录，包含运行所需文件、使用说明与相对路径 SHA-256 清单。
2. SDK 消费者检查：真实执行本地 npm 打包，再通过包入口与声明文件验证 JavaScript 导入和严格 TypeScript 编译。检查包内容，防止源码、测试、缓存、扫描图或本机信息进入交付物。
3. 保持 M3 的授权和业务边界，核对资源释放、过期与取消，以及设备引用的有效性。确证问题单独做最小修复和回归。
4. 记录实际通过项、工具限制与兼容性缺口，不把构建或模拟业务检查等同于实机验收。

本轮不引入新依赖，不改变 CI 或平台架构。产物保存在忽略目录；不执行 tag、release、npm publish 或系统安装。

## Windows 包约定

仓库根目录提供离线开发脚本：

```powershell
pwsh -File .\scripts\package-windows-dev.ps1
```

脚本要求 Windows、PowerShell 7、已安装的 .NET SDK 10 和完整的本地依赖缓存。恢复使用唯一的本地空源及已有包缓存，为各项目生成本次 Release 资产记录；缺少包时明确失败，不回退在线源。恢复和发布使用相同配置并隔离资产与输出目录，避免使用 Debug 依赖图或覆盖开发输出。文件检查或隐私检查失败会非零退出并清理本次暂存目录。实际完整发布验收结果见验证记录，局部自测不能替代完整包验收。

只验证隐私扫描与本次暂存清理，可运行 `pwsh -File .\scripts\package-windows-dev.ps1 -TestPrivacyScanner`；该模式只创建合成文件，不构建应用或读取用户数据。

- 第一个包用于 Windows x64 开发验证，使用优化的 Release 构建并关闭调试符号；它不作为正式安装程序或已签名的产品发布。
- 首轮 Release 的 `UNOB0019` 来自使用 Debug 恢复图发布。Uno SDK 的 Release 分支本来会排除 DevServer 等开发资产；恢复必须与发布配置一致，不能通过关闭优化或跳过错误解决。
- 保持当前 .NET framework-dependent 配置；以生成的 `runtimeconfig.json` 为准列出运行时要求。Windows App SDK 随包提供与 .NET 完全自包含是两个独立配置。
- 不结束正在运行的应用，不覆盖已有产物，不修改用户数据、驱动或系统注册项。构建或必要文件检查失败时返回非零状态，不输出成功包。
- 不把原图、成绩、凭据、日志、用户路径、缓存或调试符号放入包。清单只使用相对路径。
- 既有 Debug 探测产物含 Uno MCP / Hot Design 生成的绝对路径，已被隐私门禁拒绝。Release 资产记录需检查开发组件导入已排除，再对完整产物扫描；删除调试符号本身不足以解决路径问题。
- 安装器、代码签名、依赖许可清单核对、自动更新和正式分发策略仍需后续确定；没有签名或实机证据时不标为正式发布。

## SDK 包约定

`@omrina/local-sdk` 当前保持 `private: true`、版本 `0.0.0` 和零运行时依赖。构建生成 JavaScript 与 `.d.ts`，Git 忽略 `dist/`，npm 包内容包含这些文件。消费者测试使用实际 tarball 解包后的包入口，不直接引用仓库 `src/`。

打包只在本机发生。网络安装、正式包名可用性、版本策略和 npm 发布需要单独处理，不能从本地 smoke test 推导为已发布或已验证所有 JavaScript 环境。
